Inside the combo ranker

The ranker scores each of your ~116k punishes with a gradient-boosted tree ensemble: 200 small decision trees, each adding a little to the score. Below is what it responds to and why the current top combos rank where they do.

How a score is built

Each tree asks at most three yes/no questions about a punish and ends in a leaf holding a small number. One tree might look like this:

hits ≥ 6?
├─ no  → starting % < 20?  …
└─ yes → average gap < 60 frames?
          ├─ yes → kill?  yes: +0.8   no: +0.2
          └─ no  → −0.3

Trees are fitted one after another, each correcting what the sum so far gets wrong, and each scaled down to a small nudge. The score is the sum of all 200 leaves a punish lands in. Its units are log-odds of "looks like something Diego clips". Only the order is used.

What moves the score

Each curve varies one feature and keeps everything else as it was, averaged over __BGN__ of your kill punishes of 40%+. That's the group where "how good is this combo" is a real question. The vertical axis is the change in score, on the same scale in every chart, so a taller curve means a feature that matters more.

Yes/no features

The same measurement for features that are either true or false: how much the score changes going from "no" to "yes".

Why the top combos rank where they do

SHAP values split one combo's score into contributions from each feature. These add up exactly to the combo's score minus the average. Here they're grouped into the six feature families. The first ten rows are the current top 10; the last four are clips of yours, picked at random.

Reading these charts

  • Kill style, spectacle and execution barely register. Off-stage kills, down-B finishes and tech counts shift the score only a little. Your clips don't differ much from ordinary kills on those, so the model hasn't learned to care. Ratings can change that.
  • Correlated features share credit. Damage, hits and length move together, so one feature's curve understates how much the group matters. Kill is stored twice (as a flag and folded into damage); its yes/no bar toggles both.
  • Zero-to-death shows no effect because the starting-percent feature already carries that information.
  • Some features are flat. "Different moves" and "time opponent is off-stage" have no measurable effect. That's a sign they need better definitions, not proof they don't matter.
